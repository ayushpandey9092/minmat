MINIMAT PHASE 1: WHAT WE BUILT AND WHY
=======================================

PROJECT LAYOUT
--------------
minimat/
  CMakeLists.txt        build recipe: library + demo executable
  include/minimat/      PUBLIC header(s). Other code includes <minimat/Matrix.h>
    Matrix.h            declarations only (class, free functions)
  src/
    matrix.cpp          definitions (bodies) of everything in Matrix.h
    main.cpp            demo program that exercises every requirement
  build/                generated by CMake. Safe to delete.

Why this split?
- The header is what other code reads. It must say WHAT exists, not HOW.
- The .cpp holds HOW. Only the compiler needs it.
- include/minimat/ is a folder that acts like a namespace on disk. The path
  <minimat/Matrix.h> cannot clash with another library's Matrix.h.
- The library (src/matrix.cpp) is separate from the demo (src/main.cpp), so
  the demo is just one user of the library, like any other user would be.

CMakeLists.txt, line by line
- cmake_minimum_required: the oldest CMake that can read this file.
- project(minimat): gives the project a name.
- CMAKE_CXX_STANDARD 20 + REQUIRED ON: compile as C++20; fail if not possible.
- add_compile_options(-Wall -Wextra -Wpedantic): turn on warnings for all targets.
- add_library(minimat STATIC src/matrix.cpp): compile matrix.cpp into a static
  library libminimat.a.
- target_include_directories(minimat PUBLIC include): add include/ to the
  compiler's search path for the library. PUBLIC = anything linking to the
  library also gets this path.
- add_executable(minimat_demo src/main.cpp): build the demo program.
- target_link_libraries(minimat_demo PRIVATE minimat): the demo links the
  library. PRIVATE = only the demo needs it, not things that use the demo.

Build commands (from minimat/):
  cmake -S . -B build      configure: read CMakeLists.txt, make build/
  cmake --build build      compile and link
  ./build/minimat_demo     run


FUNCTIONAL REQUIREMENTS
=======================

FR-1  Construct a matrix
------------------------
What: Matrix(rows, cols) allocates rows*cols doubles with new[].
Where: matrix.cpp, the constructor.
How:  store m_rows and m_cols, then m_data = new double[rows * cols].
Concepts:
- A class with a pointer member owns heap memory. The object is on the stack
  (or wherever it lives), but its elements sit on the heap.
- The size is only known at runtime, so the storage must be dynamic.
- One flat block of rows*cols doubles, not an array of row arrays. Element
  (r, c) lives at index r*cols + c (row-major order).

FR-2  Destroy a matrix
----------------------
What: the destructor releases memory with delete[].
Where: matrix.cpp, ~Matrix().
How:  delete[] m_data;
Concepts:
- new[] must be paired with delete[]. Mixing new[] with delete is undefined
  behavior, and ASan reports it as alloc-dealloc mismatch.
- Without a destructor the memory leaks. That's the RAII motivation: the
  object cleans up after itself automatically when it leaves scope.
- The destructor runs at the end of a scope. That's why we put mat inside { }
  in main to see the count drop.

FR-3  Disable copying
---------------------
What: copy constructor and copy assignment are "= delete" until Phase 2.
Where: Matrix.h, public section.
How:  Matrix(const Matrix&) = delete;
      Matrix& operator=(const Matrix&) = delete;
Concepts:
- The compiler normally generates a copy constructor that copies the pointer
  value, not the data. Two objects then share one block, and both destructors
  delete it: a double free.
- "= delete" stops copying at compile time, so the bug can't happen silently.
- Phase 2 will write real copy operations. Moves come later too.

FR-4  Query dimensions
----------------------
What: rows() and cols() return the sizes.
Where: Matrix.h and matrix.cpp.
How:  int rows() const; int cols() const; (both return m_rows / m_cols).
Concepts:
- const on a member function means "this function does not change the
  object." The compiler enforces it.
- It's needed because free functions take const Matrix& (NFR-5). A const
  reference can only call const member functions, so rows() and cols() must be
  const or add/multiply won't compile.

FR-5  Element access
--------------------
What: two at(r, c) overloads.
  double& at(int, int)              read and write
  const double& at(int, int) const  read only
Where: Matrix.h and matrix.cpp.
How:  return m_data[index(row, col, m_cols)];
Concepts:
- Returning double& gives the caller a live reference to the element, so
  m.at(1, 2) = 5.0 writes into the matrix.
- The const overload is picked automatically when the object is const.
- Same name, same parameters, different const-ness: that's overloading on
  const. The compiler chooses by whether the object is const.
- Row-major: index = r * cols + c. For a 3x4 matrix, (1, 2) is 1*4 + 2 = 6.

FR-6  Bounds checking
---------------------
What: at() throws std::out_of_range for an invalid row or column.
Where: matrix.cpp, both at() overloads.
How:  if (row < 0 || row >= m_rows || col < 0 || col >= m_cols) throw ...
Concepts:
- Without the check, a bad index writes past the end of the heap block. That's
  silent memory corruption. The check turns it into a clear error.
- The check runs before any memory is touched.
- Caught in main with try/catch (const std::out_of_range&).

FR-7  Internal index helper
---------------------------
What: the index formula lives in an anonymous namespace in matrix.cpp.
Where: matrix.cpp, top of the file.
How:  namespace { int index(int row, int col, int cols) { return row*cols+col; } }
Concepts:
- An anonymous namespace gives internal linkage: the name is visible only in
  this .cpp file. No other file can call index().
- Compare with a function in the header, which every file that includes it
  would see. That's the point of hiding it.
- It's the same idea as a static function at file scope.

FR-8  Fill
----------
What: fill(value) sets every element.
Where: matrix.cpp.
How:  loop i from 0 to rows*cols, m_data[i] = value.
Concepts:
- Not const, because it changes the object.
- The storage is one flat block, so a single loop covers everything.

FR-9  Print
-----------
What: print(std::ostream&) const prints one row per line.
Where: Matrix.h (declaration) and matrix.cpp (body).
How:  double loop over rows and cols; os << at(i, j) << " "; then os << std::endl.
Concepts:
- const because it only reads.
- Takes std::ostream& so the caller chooses the destination: std::cout for the
  screen, an std::ofstream for a file, a string stream for a test.
- A stream is passed by reference, not copied (streams cannot be copied).
- Header uses <ostream>, which declares std::ostream. The .cpp needs it too
  for std::endl.

FR-10 Instance counter
----------------------
What: static int liveCount() returns the number of live Matrix objects.
Where: Matrix.h (declares static int count and static int liveCount()),
       matrix.cpp (defines count and liveCount).
How:  count++ at the end of the constructor, count-- in the destructor.
Concepts:
- static means one copy for the whole class, not one per object. That's why
  liveCount() can be called as Matrix::liveCount() with no object.
- A static data member is declared in the class but defined once, in a .cpp.
  Defining it in the header would give multiple definitions at link time
  (experiment E2 in the spec).
- Increment is the LAST step of the constructor. If new[] throws, the body
  stops before count++, so the count stays correct. C++ does not call the
  destructor for an object whose constructor did not finish.
- The counter is private. Only the constructor and destructor change it.
  Everyone else reads it through liveCount().

FR-11 Shape check
-----------------
What: sameShape(a, b) returns true if rows and cols match.
Where: Matrix.h (declaration), matrix.cpp (definition).
How:  a.rows() == b.rows() && a.cols() == b.cols().
Concepts:
- Free function, not a member, because it takes two matrices equally.
- Takes const Matrix& (NFR-5): it reads, it doesn't change anything.

FR-12 Addition
--------------
What: add(a, b, out) writes a + b into out. Throws invalid_argument on shape
      mismatch.
Where: matrix.cpp.
How:  check sameShape(a, b) and sameShape(a, out), then loop and out.at(i,j) =
      a.at(i,j) + b.at(i,j).
Concepts:
- The check runs before any write. If it fails, out is untouched.
- out is checked too, so the loop cannot write past the end of out's memory.
- Output is an argument, not a return value, because the caller owns out. This
  is the output-parameter style the spec uses until Phase 2.

FR-13 Multiplication
--------------------
What: multiply(a, b, out) writes a x b into out. Requires a.cols() == b.rows()
      and out sized a.rows() x b.cols().
Where: matrix.cpp.
How:  two checks first, then a triple loop:
        for i in rows of a
          for j in cols of b
            sum = 0
            for k in cols of a
              sum += a(i,k) * b(k,j)
            out(i,j) = sum
Concepts:
- Inner dimensions must match: (2x3) x (3x2) works because 3 == 3. The result
  is 2x2: rows from a, columns from b.
- Both checks run before any write, so a bad call leaves out unchanged.
- The spec does not resize out. The caller sizes it; multiply only checks.
- Hand check: [[1,2,3],[4,5,6]] x [[7,8],[9,10],[11,12]] = [[58,64],[139,154]].
  58 = 1*7+2*9+3*11. Used in main.cpp.
- Aliasing: multiply(a, b, a) would overwrite an input while still reading it.
  Not handled in Phase 1.

FR-14 Namespace
---------------
What: all public names live in namespace minimat.
Where: Matrix.h wraps the class and free functions in namespace minimat { }.
Concepts:
- Stops name clashes with other libraries. The full name is minimat::Matrix.
- In matrix.cpp, qualified definitions like minimat::Matrix::rows() put the
  body in the right namespace without a wrapper block.
- main.cpp uses minimat::Matrix, minimat::add, and so on.

FR-15 Demo
----------
What: main.cpp demonstrates every requirement above and prints liveCount()
      before, inside, and after a nested scope.
Where: src/main.cpp.
Shows:
- construction, rows/cols, at() read and write, print to a file
- liveCount() before, inside, after a { } scope
- out_of_range caught from at()
- fill
- sameShape, add, multiply on a 2x3 and 3x2 pair, with the hand-checked result
- invalid_argument caught from a bad multiply


NON-FUNCTIONAL REQUIREMENTS
===========================
NFR-1  Zero warnings under -Wall -Wextra -Wpedantic, C++20.
       Set by add_compile_options and CMAKE_CXX_STANDARD in CMakeLists.txt.
NFR-2  AddressSanitizer clean: no errors, no leaks. Not yet run.
       Note: on macOS, leak detection via ASan may not work. The `leaks`
       command is an alternative.
NFR-3  Headers contain declarations only, no non-inline function bodies.
       Matrix.h has no bodies. Good.
NFR-4  Every member function that does not modify the object is const.
       rows(), cols(), at() const, print() const.
NFR-5  Free functions take const Matrix& for inputs and Matrix& for outputs.
       sameShape, add, multiply.
NFR-6  No "using namespace std;" and no global variables.
       count is a static class member, not a global.
NFR-7  Write all code yourself. Done by hand.
